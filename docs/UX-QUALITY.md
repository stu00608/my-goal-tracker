# Native UX quality

本專案以 Awwwards、The Webby Awards、FWA 獲獎作品的設計完成度為目標，落實到原生 iPhone 的日常操作。設計與功能必須一起成立；用實際操作及畫面證據判定品質，不能以自評分數或測試通過取代 UX 檢查，也不能宣稱已獲外部獎項認證。

## 設計標準

- **動線有目的。** 每個常用操作有一條明確的主要動線。今天負責快速紀錄，目標負責分析及管理，完成負責查看里程碑與分享，設定負責偏好。卡片點擊開紀錄、長按拖曳排序；視覺上只保留有必要的操作，VoiceOver 保留等效動作。
- **內容決定層級。** 卡片以滿版圖表、照片或地圖提供概覽，標題、數值與狀態疊加在同一空間。標題、數值與選填的最後紀錄日期聚在使用者指定角落的透明文字群組，可選四個角落或隱藏；完成按鈕固定右下，不加入文字底板、額外加號或 Widget 內卡；數值主工作區置中且不包卡片。圖表四側像素內縮一致，不為文字預留大塊空白；進度環使用完整內容空間，進度數字置中且不重複於角落。優先保證文字可讀與背景可辨識；App 與 Widget 沿用一致的呈現語言。
- **相關資訊相鄰。** 控制項、說明、狀態、驗證訊息構成同一視覺群組。用間距與字級表達關係，分隔線只區分獨立操作或資料，避免把說明文字渲染成假欄位。
- **主要工作集中。** 新增紀錄的數值與照片入口位於上方，輸入、微調、預覽結果與加入附件毋須反覆捲動整頁。相同類型的操作位於一致位置；完成與新增都放右側。
- **操作可預期且可反悔。** 手勢遵守平台慣例，點按有即時回饋，鍵盤可在適當的空白處及捲動時收起。照片移除明確對應到單張縮圖，提供取消或復原；開啟照片與刪除照片有清楚區別。
- **品質涵蓋所有狀態。** 實際資料、空資料、長名稱、負數、大數、多照片、錯誤、權限拒絕與載入中的畫面都要設計。支援繁中、日文、英文、亮暗、最大無障礙字級、VoiceOver、增加對比及減少動態效果。
- **原生且有辨識度。** 以系統字體、語意色、原生導覽與 sheet 為基礎；大膽布局服務記錄任務，裝飾、動態與額外控制都必須改善理解或操作。

## 每次 UI 交付的流程

1. **釐清任務與現況。** 追蹤入口、控制項、保存與返回路徑，操作並保存現況畫面。寫下使用者要完成的任務、必要動作及本次可觀察驗收。未收到的草稿不能當成已檢視資料。使用者提供原圖時必須實際開啟，將構圖、容器、對齊及手勢列為驗收，最後實際 render 要逐項對照原圖；不得以只讀文字或測試通過宣稱相符。
2. **比較設計。** 新增或重做主要輸入／附件／導覽模式時，至少比較三種實質不同的原生方案，從操作次數、捲動距離、資訊層級、誤操作、可讀性及無障礙選擇方案；將候選與理由保存在本次報告。小幅修正聚焦受影響的模式。
3. **實作並操作。** 用 Simulator 執行主要與例外流程，保存真實畫面。複雜的新模式另呈現至少一個可比較的替代布局；允許 DEBUG-only 原型，但正式產品只保留選定方案。
4. **自我批評與獨立檢查。** 檢視實際截圖與手勢結果，逐項列出不必要動線、錯位、截斷、對比、分組、鍵盤、誤刪及狀態遺失等問題。複雜 UX 使用獨立設計檢查；使用者指定模型時遵從，其他情況沿用 Orca launcher 設定。
5. **修正後重看。** 修正所有已發現的視覺／操作問題，重新執行受影響流程並檢視新畫面；反覆進行直到以下條件全數成立。最後一次改動後的畫面才是交付證據。
6. **記錄與交付。** 報告選定方案、迭代發現與修正、實際驗收、未能驗證的裝置行為。接續專案既定測試、PR／最新 head CI、合併與真機安裝流程。

## 必須全部成立的驗收條件

- 每個畫面有清楚主工作；所有可見動線及控制都能說明用途，沒有本次已知的重複或多餘入口。
- 常用紀錄流程的數值與加照片入口位於同一個上方工作區，附件操作明確對應到該張照片。
- 文字與圖像不裁切、不因語言或字級使操作失效；控制項及其說明保持分組，對比足以辨識。
- 用手指與 VoiceOver 都能完成主要工作，互動範圍符合 iPhone 慣例，拖曳、sheet、照片檢視與鍵盤回應自然。
- 捲動、選圖、取消移除、放大返回、切換輸入模式後，輸入草稿與已保存資料正確。
- 亮暗、三語及最大無障礙字級的實際畫面已檢視；受影響的 Widget 使用原生主畫面呈現檢查，涵蓋原色／深色／調色／透明模式與設定所選目標。
- 所有已知 UX／視覺問題都有修正後證據；未執行的檢查明確列為未驗證，不能算通過。

## 參考與適用範圍

[Awwwards 評估系統](https://www.awwwards.com/about-evaluation/)以設計、易用性、創意與內容評估作品；[Mobile Excellence](https://www.awwwards.com/mobile-excellence-guidelines.pdf)提供行動可讀性、操作目標、表單與圖片檢視等檢查。這些原則轉成原生檢查，不套用網站專屬的 SEO 或 PWA 項目。

[The Webby Awards 的 Apps, Software & Immersive 準則](https://www.webbyawards.com/judging-criteria/)包含導覽、視覺、功能、互動、執行與整體體驗；本專案採取其中對使用者任務與原生媒介有意義的品質要求。

[FWA 的官方定位](https://thefwa.com/FWA25/25.html)重視數位設計的創意、原創與技術完成度；本專案的辨識度來自有意義的互動與清楚資料呈現。

[Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/)與 apple-design skill 提供平台慣例、可讀性、直接操作與減少動態效果的依據。以上為品質目標及本專案採用的檢查，外部得獎需由各獎項評審判定。
